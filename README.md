## Zibal Payment Gateway for PrestaShop

درگاه پرداخت زیبال برای پرستاشاپ — نسخه 2.0.0

این ماژول با تمامی نسخه‌های پرستاشاپ از 1.7 به بعد (1.7.x، 8.x و 9.x) قابل استفاده است؛ یک فایل نصب برای همه نسخه‌ها.

**سازگاری:** PrestaShop 1.7.0 تا 9.x — PHP 5.4 تا 8.4 (مطابق نیاز هر نسخه پرستاشاپ)
**پیش‌نیاز:** افزونه cURL در PHP، و MySQL/MariaDB (برای قفل `GET_LOCK`)

## نصب

1. فایل `zibalpayment-2.0.0.zip` را از بخش «ماژول‌ها ← بارگذاری ماژول» نصب کنید (پوشه داخل zip باید `zibalpayment` باشد).
2. در تنظیمات ماژول، شناسه درگاه (مرچنت) را وارد کنید. برای تست از `zibal` استفاده کنید.
3. واحد پول را انتخاب کنید:
   - **این درگاه فقط با ریال و تومان کار می‌کند** (کد ارز `IRR`، `IRT`، `TOM` یا `TMN`). برای ارزهای دیگر گزینه پرداخت نمایش داده نمی‌شود و هیچ تبدیل نرخ ارزی انجام نمی‌شود.
   - **خودکار:** ارز با کد `IRR` ریال و بقیه کدها تومان در نظر گرفته می‌شوند.
   - اگر ارز را با کد `IRR` ساخته‌اید ولی قیمت‌ها به تومان است، «تومان» را انتخاب کنید.
4. در «پرداخت ← ترجیحات» مطمئن شوید ارز و کشورهای موردنظر برای ماژول فعال است.
5. اگر در پنل زیبال محدودیت IP فعال است، IP سرور فروشگاه را ثبت کنید (در غیر این صورت تأیید پرداخت با کد 115 رد می‌شود).

## ارتقا از نسخه 1.x

zip جدید را مانند نصب بارگذاری کنید؛ اسکریپت `upgrade/upgrade-2.0.0.php` به‌طور خودکار اجرا می‌شود
(ساخت جدول تراکنش‌ها، اصلاح تنظیمات ارز نسخه قدیمی، ثبت هوک‌ها).

## رفتار پرداخت

- هر تراکنش (trackId، مبلغ ریالی، مرچنت) **قبل از رفتن به درگاه** در جدول `zibal_transaction` ذخیره می‌شود. بازگشت فقط برای trackId همان سبد پذیرفته می‌شود و مبلغ تأییدشده باید با مبلغ ذخیره‌شده و سبد فعلی برابر باشد.
- آدرس بازگشت با HMAC امضا می‌شود و سبد از آن خوانده می‌شود، نه از کوکی؛ بازگشت از مرورگر دیگر پرداخت را از بین نمی‌برد.
- رفرش صفحه بازگشت یا بازگشت هم‌زمان باعث سفارش تکراری نمی‌شود (قفل پایگاه داده).
- verify و inquiry همیشه با مرچنتی انجام می‌شوند که تراکنش با آن ساخته شده است.

### وضعیت‌های تراکنش

| وضعیت | معنی |
|---|---|
| `pending` | ارسال به درگاه؛ هنوز تأیید نشده (خطای شبکه یا تنظیمات هم در همین وضعیت می‌ماند تا قابل تکرار باشد) |
| `verified` | زیبال تأیید کرد؛ سفارش در حال ثبت |
| `paid` | سفارش ثبت شد |
| `mismatch` | پول کسر شده ولی مبلغ با سبد نمی‌خواند؛ سفارش در وضعیت «خطای پرداخت» ثبت شد |
| `inquiry` | زیبال گفت «قبلاً تأیید شده» (201) ولی استعلام هنوز تأیید نشد؛ با رفرش دوباره استعلام می‌شود |
| `failed` | پرداخت نشده، لغو شده یا پول به کارت برگشته است |

- اگر مشتری برای همان سبد دوباره «پرداخت» بزند و تراکنش قبلی پرداخت شده باشد، همان تراکنش قبلی تکمیل می‌شود. اگر وضعیت تراکنش قبلی قابل استعلام نباشد، پرداخت جدید ساخته نمی‌شود (جلوگیری از کسر دوباره).
- خطاهای تنظیمات (مرچنت نامعتبر/غیرفعال، IP ثبت‌نشده: 102، 103، 104، 115) پرداخت را «ناموفق» نمی‌کنند و با سطح بحرانی در لاگ ثبت می‌شوند.

### پیام‌های خصوصی سفارش

- پرداخت موفق: `Zibal trackId: … | refNumber: … | card: … | amount: … IRR`
- اگر قبل از موفقیت خطایی رخ داده باشد (متن خام cURL، یا result/message/status زیبال)، تاریخچه خطاهای هر تلاش به‌صورت پیام خصوصی جداگانه روی سفارش ثبت می‌شود. این پیام‌ها برای مشتری نمایش داده نمی‌شوند.
- خطاهای تلاش‌هایی که هرگز به سفارش نرسیدند، در فهرست «تراکنش‌های نیازمند بررسی» و لاگ پرستاشاپ قابل مشاهده‌اند.

### صفحه تنظیمات ماژول

زیر فرم تنظیمات، فهرست «تراکنش‌های نیازمند بررسی» (verified / inquiry / mismatch و تراکنش‌های در انتظارِ دارای خطا) با دکمه «استعلام مجدد» نمایش داده می‌شود که پاسخ فعلی زیبال را نشان می‌دهد.
